# Анимации открытия и апгрейда

Добавлены animations.js и animations.css, подключённые в miniapp.html.

- Открытие: лента с центральным указателем, 2,6 секунды, затем карточка реально выданного сервером предмета. Декоративные позиции выбираются из состава кейса по весам; они не определяют выигрыш.
- Апгрейд: исходный предмет и цель, круг с сектором вероятности, вращение 2,1 секунды, отдельные состояния успеха и неудачи. Конечный угол иллюстрирует серверный результат, это не доказательство случайности.
- Пропуск анимации без нового API-запроса. Поддержка prefers-reduced-motion, завершение при сворачивании во время движения.
- Тактильный отклик Telegram, мягкое появление результата/разделов, состояния ожидания.
- В инвентарь добавлены изображения.
- Один игровой запрос за раз в текущем интерфейсе. Серверная идемпотентность сохранена. При неопределённом сетевом результате сохранённый request_id используется кнопкой проверки операции в профиле.
- Таймаут ожидания заголовков API — 25 секунд. Ошибка обновления профиля после подтверждённой операции не выдаётся за ошибку списания.

Кнопка открытия осталась выше состава кейса. Балансировка, админ ID и логика начисления не менялись. Внешняя выдача не подключена, приём Stars этой сборкой не включается.

Проверки: 17 существующих тестов (game/balance/stars/catalog/HTTP) и 4 теста анимационной логики в QuickJS с минимальной моделью DOM. JS синтаксис проверен QuickJS; node в среде отсутствует. Браузер Chromium не запустился, поэтому эти проверки НЕ заменяют визуальный тест Telegram/WebView.

Перед публикацией проверить в Telegram: открытие обычного/ALL IN кейса, пропуск, повтор после сетевого сбоя, оба исхода апгрейда, маленький экран, reduced motion и сворачивание. Не делать повторное списание вручную при потере связи: использовать проверку операции.
